# Industry Translation Profiles

Use these to describe real experience in the target industry's vocabulary. Translate only when the underlying work truly matches the concept. Never claim direct industry experience that the candidate does not have.

## Finance / Banking
- Vocabulary: risk, fraud detection, regulatory compliance, auditability, data governance, data lineage, data quality, transaction data, cost optimization
- Valid translations:
  - Threshold or status-change alerting → anomaly and exception monitoring
  - CDC / SCD Type 2 history → auditable historical tracking
  - Schema-drift handling and data validation → data quality and governance
  - Read-only roles and SQL validation → access control and secure data handling

## Healthcare / Pharmacy
- Vocabulary: PHI/PII, HIPAA-aligned data handling, claims, patient outcomes, data privacy, compliance
- Valid translations:
  - Hiding personal columns from LLM context → PII protection in data workflows
  - Validation pipelines → data integrity for regulated reporting

## Manufacturing / Semiconductor
- Vocabulary: yield, tool uptime, equipment monitoring, SPC, process control, fab data, downtime reduction, root-cause analysis
- The candidate has direct experience here (wafer monitoring, production lines, boiler sensors, RF testing). Use this vocabulary directly and put it first.

## Retail / E-commerce
- Vocabulary: orders, returns, sales, revenue, merchandising, product catalog, customer segments, multi-currency, promotions and coupons
- The candidate has project work here, not employment (Projects 5 and 6). Put those projects first for retail JDs.
- Valid translations:
  - Cleaning duplicate orders and mixed formats → order data quality
  - SCD Type 2 product snapshot → product catalog history
  - Revenue by category, brand or customer group → merchandising and sales reporting
  - Converting 7 currencies to one → multi-currency revenue reporting

## Transportation / Mobility
- Vocabulary: trips, rides, drivers, riders, cities or markets, trip-level data, real-time ingestion, ride ratings
- The candidate has project work here, not employment (Projects 7, 11 and 13). Put those projects first for mobility JDs.
- Valid translations:
  - Auto Loader streaming from S3 → real-time trip data ingestion
  - City-level views → market-level reporting for city teams
  - Rider and driver roles (Project 11) → rider and driver data models, for software-leaning JDs only

## SaaS / GTM (B2B software, sales and go-to-market analytics)
- Vocabulary: pipeline, bookings, renewals, retention, churn, ARR, territory, funnel, CRM (Salesforce), product usage, field sales and customer success teams
- The candidate has no sales or GTM data on file. Never use pipeline, bookings, churn, retention, ARR or territory as something the candidate worked on; those requirements go to Gap Triage.
- Valid translations:
  - Dashboards built for client teams and engineers (UL) → reporting for customer-facing and internal teams
  - Flagging underperforming shifts against rolling baselines (Keysight) → tracking performance against baselines
  - Automated recurring reports and alerts → self-serve and automated reporting

## Tech / General and Other
- No translation profile. Use the JD's own vocabulary only where the underlying work matches, and lead with the candidate's strongest general data work.

## Translation rules
- A translation applies only when its source fact is on the attached resume or in the Evidence Bank. The examples above name where the fact usually lives; check it is there before using it.
- Translate the concept, not the industry. "Built anomaly alerting" is allowed; "Worked in banking" is not.
- Put the domain keyword in the Summary only when at least one bullet supports it.
- If the JD requires direct industry experience (for example, "3+ years in financial services"), mark it as a Hard gap.
