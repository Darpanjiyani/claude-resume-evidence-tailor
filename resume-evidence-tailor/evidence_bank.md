## Project Library

Every project you have built. For each job, the skill scores these against the JD and picks the best ones for the Projects section.

Field guide:
- **Status:** Completed / In progress / Planned. Planned projects never go on the resume; they can only be suggested in Gap Triage.
- **Origin:** Course project / Capstone / Self-designed / Tutorial-based. Tutorial-based projects are described at the level of what you built and can explain, never as original design.
- **Team / my part:** For team projects, bullets may claim only the parts listed under "My part". Team-level work is described as team work ("Team built...", "Contributed ... to a 5-person team ...").
- **Best for roles:** Role types this project suits. "X only" or a condition (for example "only when the JD asks for Kafka") is a hard filter.
- **Domain:** Industry the project's data comes from, using the skill's industry names (Finance/Banking, Healthcare/Pharmacy, Manufacturing/Semiconductor, Retail/E-commerce, Transportation/Mobility, SaaS/GTM, Tech/General).
- **Link:** The GitHub URL that goes on the resume next to the project title. A URL here is confirmed; a bracketed link is not.
- **Co-authors listed:** You built the whole project, but the submitted report or notes list other names. Bullets may say "Built", "Trained", "Deployed" for all of the work. Never write "solo", "independently", "single-handedly", "led a team", or a team size, so the resume stays consistent with the public report.
